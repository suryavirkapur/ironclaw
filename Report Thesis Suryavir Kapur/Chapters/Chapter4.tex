\section{Experimental Design}
The evaluation is designed to allow for the independent measurement of three
claims; namely utility, security and systems performance. The utility aspects are
evaluated by comparing the task results achieved when employing either
fixed-tool or dynamic-tool agents. The security aspects are tested through
attempting to breach containment generated by the use of an adversarially
created codebase. Finally, the performance characteristics of moving the
execution point of a process-level sandbox into a Firecracker microVM are
measured. Figure 4.1 describes the three independent evaluation axes used in the
evaluation.

\section{Baselines}
Three different execution modes have been compared;

\noindent Process baseline: An openclaw style process level execution environment
that executes the generated code without the boundaries of a microvm.

\noindent MicroVM fixed-tool baseline: IronClaw with firecracker isolation but
only exposes predefined tools.

\noindent Target System: IronClaw, firecracker isolation and dynamic tool
synthesis enabled

\section{UTILITY EVALUATION AND SECURITY EVALUATION}
Utility evaluation and security evaluations will be done by using complex
software engineering and data analysis-type tasks. These tasks have multiple
intermediate steps, such as; repository inspections, configuration validations,
parsing logs, aggregating benchmarks and small bug fix type workflows (using
similar style to SWE-bench) are possible candidate types. In addition to
completion rates, metrics for utility and security evaluation will also include,
total number of turns required for a task to complete, number of tool calls used
during a task execution, amount of tokens used in an execution, whether or not
the user’s response to a task was correct based on validation of their response.

\section{Performance Profiling}
Performance Profiling will measure the total dynamic tool loop from prompt,
generated code, guest execution, output transfer and finally result
interpretation. The primary performance profile metrics include:
\begin{itemize}
    \item MicroVM Initialization Latency
    \item Execution Latency
    \item Memory Overhead
    \item CPU Utilization
    \item Output Size
    \item Failure Recovery Time
\end{itemize}

Benchmark Target (Initialization Latency) -- $< 500$ms for all executions
resumed via snapshots.
